Travlr Getaways – Full Stack Web Application
CS 465 Module Eight Journal Reflection
Architecture
In this project, I used two different frontend development approaches: the Express-based HTML/JavaScript pages for the customer-facing site and the Angular single-page application (SPA) for the administrative interface. The Express frontend uses server-rendered Handlebars templates, which refresh the entire page whenever new data is requested. This approach works well for static or lightly dynamic content. In contrast, the Angular SPA provides a much richer and more responsive experience. It updates the interface dynamically without reloading the page, uses components and services to organize logic, and communicates with the backend through asynchronous API calls. This makes the admin interface feel faster and more interactive.

The backend uses a NoSQL MongoDB database because the data in this application trips, bookings, users, and itineraries, is flexible and does not always fit neatly into rigid relational schemas. MongoDB’s document-based structure allows the application to store JSON-like objects directly, which aligns naturally with the JavaScript-based MEAN stack. It also scales easily and works well with Mongoose for modeling and validation.

Functionality
JSON is different from JavaScript because JSON is strictly a data format, while JavaScript is a full programming language. JSON cannot contain functions or logic; it only stores structured data using key-value pairs. JSON ties the frontend and backend together because both Express and Angular consume and produce JSON when communicating with the API. This makes it easy to pass trip data, user information, and booking details between the server and the client.

Throughout the full stack process, I refactored code several times to improve functionality and efficiency. For example, I moved repeated database logic into reusable Mongoose models and cleaned up Angular components by shifting repeated API calls into shared services. Reusable UI components in Angular, such as trip cards and form components, made the admin interface more consistent and easier to maintain. When I updated one component, the changes automatically applied wherever that component was used.

Testing
Testing the API required checking multiple HTTP methods like GET, POST, PUT, and DELETE to ensure each endpoint behaved correctly. I tested endpoints using tools like Postman and by verifying that the Angular SPA could retrieve and update data through the API. Security added another layer of complexity because admin-only endpoints required a valid JWT token. This meant testing not only the endpoint itself but also the authentication flow: logging in, receiving a token, storing it, and sending it with each protected request. Understanding how methods, endpoints, and security interact is essential in a full stack application because every layer must work together to ensure both functionality and protection of sensitive data.

I learned how to design architecture, build RESTful APIs, work with MongoDB, and develop both server-rendered and SPA frontends.
